# Deviations from the specification (V2.8)

"None" is the expected answer (doc 17). Each item here was required by the owner or by the platform, or is a known gap.

| Spec | What differs | Why |
|---|---|---|
| D-069 / D-083 | Vercel static output + Vercel Functions in `api/v1/` (doc 32 §2 mapping). | Owner instruction; V2.8 confirms Vercel. |
| 12 (CSP), doc 29 reference markup | Per-page `<meta>` CSP with SHA-256 hashes of each page's inline scripts **and inline style attributes** (`'unsafe-hashes'`), built by `scripts/postbuild.ts`. `'unsafe-inline'` is not used. | React Router prerender writes page-specific inline scripts, and the V2.8 reference screens use inline `style` attributes for layout. Hashing keeps both strict. |
| ADR-008 prerender, checklist 11.3 | (Accepted by the owner, 26 Oct 2026.) **Learning-path pages** (`/tools/{tool}/roadmap`, `/tools/{tool}/for/{x}`) and combined toolkits render in the browser from `/data/tool/*.json` and `/data/id/*.json` instead of being prerendered. 5,874 pages are prerendered. | Keeps the static output under host limits (prerendering every path would be about 17,000 files). Those routes need JavaScript. |
| 14 (404 status) | Unknown paths are served `__spa-fallback.html` (S24 with HTTP 200). | Same rewrite serves the client-rendered routes. |
| 04 S08 | Tools A–Z without JavaScript lists one letter at a time. | 1,781 tools on one page is too heavy for phones. |
| Doc 29 §5 | `Picture`, `ToolLogo`, `Icon` are ported into `app/components/da.tsx` (same markup and `data-da`), reading maps generated into `app/generated/` from `public/assets`. | Vite cannot import modules from `public/`. |
| Doc 29 L4 | `check-design.mjs` runs on `app/` and `src/` (this repo's layout). Its built-in token check fails on Windows paths; tokens are verified by regenerating and diffing. | Tooling path handling. |
| 22 §6.5 feature flags | **Every flag is on** in every build (owner decision, 26 Oct 2026). `FLAG_<NAME>=off` still turns one off. | Owner: "nothing hiding behind any flag". |
| 24 §7–§11, S44–S48, A01 | Accounts, consent, sync, recommendations R1–R8, trending, suggestion status, contributors and the admin report run on **demo data**: a demo account kept in `localStorage` (`da.account.v1`), deterministic sample trending counts (`public/data/trending.json`, `demo: true`), sample contributor names, sample review status, sample visitor signals in A01. Every demo surface is labelled "Preview" or "Sample". | Owner decision: show what the live product feels like before the auth stack (Spike S-2), Neon and real users exist. Replace before public launch. |
| D-093 TrustLine | All 1,781 profiles currently show **Preview**: none has a dated price check (the five `web_seen` profiles checked existence and purpose only). The "Checked {date}" chip appears automatically once a price is checked. | FR-096: the label comes off only when the price has a source and date. **Owner decision (26 Oct 2026): "partly checked" stays Preview.** The 12 audit failures for `[data-da=verified]` on 07/08/17 are this, and clear on their own once an editor records a dated price check. |
| New compositions | Helpers index (from 09 + 15), need (07), sector (04 + 05), skills (06), skill (07 + 15), tools (05) and the V2 records (07 + 10 stepper) have no reference screen; they are composed from `da.css` parts, as the concept board's screens suggest. | Needs design review (CLAUDE.md). |
